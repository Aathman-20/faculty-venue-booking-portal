# Faculty Venue Booking Portal

This is the Faculty Venue Booking Portal, a web application built using AngularJS, Node.js + Express, and MongoDB Atlas.

## Experiment 11 – CI/CD Pipeline

The project implements a full CI/CD pipeline leveraging GitHub Actions.

1. **Git repository**: The source code is hosted on GitHub.
2. **GitHub Actions**: Continuous Integration is handled using a GitHub Actions workflow (`.github/workflows/ci.yml`).
3. **Automatic workflow trigger**: The workflow is automatically triggered on `push` and `pull_request` events targeting the `main` branch.
4. **Node.js setup**: The workflow sets up Node.js (version 18) to support the backend Express server.
5. **Python setup**: The workflow sets up Python (version 3.11) to run the automated Selenium test suite.
6. **Dependency installation**: Node modules are installed using `npm ci` within the `server` directory, and Python dependencies are installed using `pip install -r tests/selenium/requirements.txt`.
7. **Backend startup**: The backend server is started as a background process using `npm start` in the `server` directory.
8. **Frontend startup**: The AngularJS frontend is served on port 8000 using Python's built-in `http.server` as a background process.
9. **Selenium execution**: Headless Chrome is invoked via Python Selenium to run both the main functionality tests and the novelty tests.
10. **Test result**: If any automated test fails, the CI workflow fails immediately, ensuring broken code is not merged. If all tests pass, the pipeline succeeds.
11. **Artifact collection**: Screenshots and other test outputs generated by Selenium are automatically uploaded and stored as GitHub Actions artifacts for debugging.
12. **Deployment status**: CD (Continuous Deployment) is currently configured as a placeholder. Deployment to a hosting provider requires linking to an actual service (e.g., AWS, Render) and providing deployment secrets.

### GitHub Secrets Configuration

The CI/CD pipeline requires the following GitHub Secrets to interact with external services securely:

* `MONGO_URI`: The MongoDB Atlas connection string (e.g., `mongodb+srv://<username>:<password>@cluster.mongodb.net/?retryWrites=true&w=majority`).
* `MONGO_DB_NAME`: The name of the specific database to connect to (e.g., `venue_booking_db`).

*Do not expose these credentials directly in the codebase or version history.*
